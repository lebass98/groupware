# AGENTS.md

## Git 커밋 및 작업 내역 규칙 (Git Commit & Changelog Guidelines)

- **자동 커밋 메시지 한글 작성 의무화**:
  - 코드 변경 사항 작성 완료 및 검증 후, Git 커밋을 수행할 때 **커밋 메시지는 반드시 명확한 한글(한국어)**로 작성합니다. (영문 커밋 메시지 사용 금지)
  - 커밋 메시지 형식 컨벤션:
    - `기능: [기능 설명]` (e.g. `기능: 임직원 주소록 목록 및 상세 보기 화면 구현`)
    - `수정: [수정 내용]` (e.g. `수정: GitHub Pages 프로필 이미지 로컬 다운로드 연동`)
    - `스타일: [스타일/UX 변경]` (e.g. `스타일: 하단 독 메뉴 5개 핵심 항목으로 정리`)
    - `문서: [문서 업데이트]`

- **작업 내역 자동 업데이트 요약 작성 (README.md Changelog Summary Automation)**:
  - 기능 구현, 수정, 스타일 조정 등 사용자 요청 작업 완료 시, `README.md` 하단의 `📅 작업 내역 (Work History)` 섹션에 해당 일자(YYYY-MM-DD)별 작업 내역을 **장황한 설명 없이 최대한 간략하고 명확한 핵심 위주의 1줄 요약 불릿 형태**로 자동 기록/업데이트합니다.

- **자동 커밋, 푸시, 풀다운 자동화**:
  - 규칙 추가 또는 기능 구현 명령이 완료되면 변경사항에 대해 한국어로 명확히 번역하여 커밋 메시지를 작성한 후 `git commit`, `git push`, `git pull`을 순서대로 자동 실행하여 저장소 상태를 동기화합니다.

## UI 및 컴포넌트 정책 규칙 (UI & Component Policy Guidelines)

- **기존 디자인 시스템 및 UI 스타일 임의 변경 금지 (Design System Integrity)**:
  - WnC 그룹웨어의 고유 UI/UX 디자인 시스템(Glassmorphism, Bento Grid 레이아웃, CSS 변수 및 Tailwind 테마 컬러 토큰, Pretendard 타이포그래피, 라운딩 및 카드 컴포넌트 룩앤필 등)은 사용자의 명시적인 디자인 변경 지시가 없는 한 **절대 임의로 변경하거나 다른 스타일로 대체하지 않고 100% 원형을 엄격히 보존**합니다.
  - 신규 모션(Framer Motion 등), 애니메이션, 기능 추가 작업 시에도 기존의 시각적 디자인 스타일 및 레이아웃 구조를 완벽히 유지한 상태에서 기능과 모션만을 조화롭게 결합합니다.

- **주소록 상단 카테고리 탭 팀(부서) 구분 고정**:
  - 주소록 화면의 상단 칩 카테고리 구분은 반드시 **팀(부서)** 기준(`전체`, `경영지원팀`, `기획팀`, `디자인팀`, `퍼블리싱팀`, `개발팀`, `전략본부`, `수행본부`)으로 고정하며, 상태 필터 탭 등으로 임의 변경하지 않습니다.

- **아이콘 구현 시 Material Symbols 웹폰트 사용 금지 및 100% SVG 벡터 사용 의무화**:
  - 앞으로 UI 아이콘을 추가하거나 수정할 때는 웹폰트(`<span class="material-symbols-outlined">`)를 절대 사용하지 않고, 반드시 **인라인 SVG 코드(`<svg ... viewBox="0 0 24 24" fill="currentColor">`)** 또는 `data/svgIcons.js`의 `getSvgIcon()` 헬퍼를 사용하여 구현합니다.
  - 신규 아이콘이 필요한 경우 `data/svgIcons.js`의 `SVGIcons` 딕셔너리에 해당 아이콘의 공식 SVG 경로(path)를 함께 추가 및 등록하여 관리합니다.

## 파일 시스템 및 환경 관리 규칙 (File System & Environment Guidelines)

- **macOS AppleDouble(`._*`) 메타데이터 파일 생성 즉시 삭제 의무화**:
  - 외장하드(FAT/exFAT/NTFS/HFS+ 등) 및 macOS 환경 작업 중 생성되는 모든 `._*` (AppleDouble 리소스 포크 파일), `.DS_Store` 등의 임시/메타데이터 파일은 **발견되거나 생성되는 즉시 삭제(`find . -name "._*" -delete` 또는 `dot_clean .`)**합니다.
  - Git 스테이징 및 커밋 전 항상 `._*` 파일 존재 여부를 점검하고 전량 삭제하여 저장소에 절대 포함되지 않도록 유지합니다.
