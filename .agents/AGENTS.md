# AGENTS.md

## Git 커밋 및 작업 내역 규칙 (Git Commit & Changelog Guidelines)

- **자동 커밋 메시지 한글 작성 의무화**:
  - 코드 변경 사항 작성 완료 및 검증 후, Git 커밋을 수행할 때 **커밋 메시지는 반드시 명확한 한글(한국어)**로 작성합니다. (영문 커밋 메시지 사용 금지)
  - 커밋 메시지 형식 컨벤션:
    - `기능: [기능 설명]` (e.g. `기능: 임직원 주소록 목록 및 상세 보기 화면 구현`)
    - `수정: [수정 내용]` (e.g. `수정: GitHub Pages 프로필 이미지 로컬 다운로드 연동`)
    - `스타일: [스타일/UX 변경]` (e.g. `스타일: 하단 독 메뉴 5개 핵심 항목으로 정리`)
    - `문서: [문서 업데이트]`

- **작업 내역 자동 업데이트 요약 작성 (README.md Changelog Summary Automation)**:
  - 기능 구현, 수정, 스타일 조정 등 사용자 요청 작업 완료 시, `README.md` 하단의 `📅 작업 내역 (Work History)` 섹션에 해당 일자(YYYY-MM-DD)별 작업 내역을 **장황한 설명 없이 최대한 간략하고 명확한 핵심 위주의 1줄 요약 불릿 형태**로 자동 기록/업데이트합니다.

- **자동 커밋, 푸시, 풀다운 자동화 및 동기화 시 ._* 파일 삭제 의무화**:
  - 규칙 추가 또는 기능 구현 명령이 완료되면 변경사항에 대해 한국어로 명확히 번역하여 커밋 메시지를 작성한 후 `git commit`, `git push`, `git pull`을 순서대로 자동 실행하여 저장소 상태를 동기화합니다.
  - **Git 풀(`git pull`)을 받아 저장소를 동기화할 때나 동기화 직후, 또는 작업 중 어떠한 순간에도 `._*` (AppleDouble) 파일이 발견되거나 생성되면 즉시 무조건 전량 자동 삭제(`find . -name "._*" -delete` 또는 `dot_clean .`)**합니다.

## UI 및 컴포넌트 정책 규칙 (UI & Component Policy Guidelines)

- **기존 디자인 시스템 및 UI 스타일 임의 변경 금지 (Design System Integrity)**:
  - WnC 그룹웨어의 고유 UI/UX 디자인 시스템(Glassmorphism, Bento Grid 레이아웃, CSS 변수 및 Tailwind 테마 컬러 토큰, Pretendard 타이포그래피, 라운딩 및 카드 컴포넌트 룩앤필 등)은 사용자의 명시적인 디자인 변경 지시가 없는 한 **절대 임의로 변경하거나 다른 스타일로 대체하지 않고 100% 원형을 엄격히 보존**합니다.
  - 신규 모션(Framer Motion 등), 애니메이션, 기능 추가 작업 시에도 기존의 시각적 디자인 스타일 및 레이아웃 구조를 완벽히 유지한 상태에서 기능과 모션만을 조화롭게 결합합니다.

- **주소록 상단 카테고리 탭 팀(부서) 구분 고정**:
  - 주소록 화면의 상단 칩 카테고리 구분은 반드시 **팀(부서)** 기준(`전체`, `경영지원팀`, `기획팀`, `디자인팀`, `퍼블리싱팀`, `개발팀`, `전략본부`, `수행본부`)으로 고정하며, 상태 필터 탭 등으로 임의 변경하지 않습니다.

- **아이콘 구현 시 Material Symbols 웹폰트 사용 금지 및 100% SVG 벡터 사용 의무화**:
  - 앞으로 UI 아이콘을 추가하거나 수정할 때는 웹폰트(`<span class="material-symbols-outlined">`)를 절대 사용하지 않고, 반드시 **인라인 SVG 코드(`<svg ... viewBox="0 0 24 24" fill="currentColor">`)** 또는 `data/svgIcons.js`의 `getSvgIcon()` 헬퍼를 사용하여 구현합니다.
  - 신규 아이콘이 필요한 경우 `data/svgIcons.js`의 `SVGIcons` 딕셔너리에 해당 아이콘의 공식 SVG 경로(path)를 함께 추가 및 등록하여 관리합니다.

- **PC 메인 대시보드 구성요소 명칭 '위젯(Widget)' 표준화**:
  - PC 메인 대시보드에 배치된 모든 개별 카드 컴포넌트(프로필, 연차/휴가 현황, 생일자, 전체 일정표, 공지사항, 주간 업무 보고, 오늘의 일정, 근태 & 출/퇴근, Quick Action, To-Do List 등)는 공식 명칭을 **'위젯(Widget)'**으로 통일하여 지칭 및 관리합니다.

- **모바일 메인 화면 명칭 '모바일 메인' 표준화**:
  - 모바일의 메인 홈/진입 화면은 공식 명칭을 **'모바일 메인'**으로 통일하여 지칭 및 관리합니다.

- **메인 캘린더 위젯 명칭 '캘린더' 표준화 및 인라인 일정 인터랙션 규칙**:
  - 모든 디바이스(PC 대시보드 및 모바일 메인)에서 기존 '근태일지' 명칭을 **'캘린더'**로 공식 변경 통일합니다.
  - 메인의 캘린더 위젯에서 일자를 클릭할 때 모달 팝업을 띄우지 않고, **하단의 일정 영역 데이터(날짜 헤더 및 일정 목록)를 선택한 일자의 일정으로 즉시 교체/연동**하여 표시합니다.


## 데이터 아키텍처 및 디바이스 동기화 규칙 (Data Architecture & Cross-Device Synchronization Guidelines)

- **모든 디바이스 투데이(모바일 메인)와 메인(PC 대시보드) 데이터 100% 상시 실시간 동기화 의무화 (Universal Cross-Device Data Synchronization)**:
  - PC 메인 대시보드, 모바일 메인(투데이), 태블릿, 모바일 앱(React Native WebView/Expo) 등 모든 디바이스 환경에서 취급되는 모든 사용자 상태 및 비즈니스 데이터(프로필, 근태/출퇴근 상태 및 출퇴근 시간, 연차/휴가 잔여·사용·총 현황 및 최근 신청 이력, 캘린더 월간 일정 및 일자별 선택 일정, 공지사항 및 읽음 상태, To-Do 할 일 목록 및 완료 체크 여부, 프로젝트 현황 통계, 경비 내역 및 미청구 건수, 결재 내역 및 대기 건수, 알림 센터 등)는 **반드시 단일 마스터 스토리지(LocalStorage `wordncode_groupware_state`, `wordncode_groupware_projects`, `wordncode_notifications_read_state` 및 MockData)를 공유하여 100% 동일하게 상시 실시간 동기화**되어야 합니다.
  - 하나의 디바이스(예: PC 웹 대시보드)에서 발생한 모든 데이터 변경사항(출근/퇴근 클릭, 알림 읽음 처리, 투두 완료/추가, 휴가 신청, 결재 승인, 경비 청구 등)은 스토리지 이벤트(`storage` 이벤트 리스너) 및 공통 동기화 레이어를 통해 다른 모든 열려있는 창과 디바이스(모바일 메인 등) 화면에 즉시 실시간으로 무조건 자동 반영되어야 합니다.
  - 디바이스별로 서로 다른 임의의 Mock 데이터를 하드코딩하거나 독립적인 상태를 분리 생성하여 디바이스 간 데이터 불일치가 발생하는 것을 절대 금지합니다.

## 파일 시스템 및 환경 관리 규칙 (File System & Environment Guidelines)

- **macOS AppleDouble(`._*`) 메타데이터 파일 생성 즉시 무조건 전량 삭제 의무화 (Zero Tolerance Policy)**:
  - 외장하드(FAT/exFAT/NTFS/HFS+ 등) 및 macOS 환경 작업 중 생성되는 모든 `._*` (AppleDouble 리소스 포크 파일), `.DS_Store` 등의 임시/메타데이터 파일은 **생성되는 즉시 또는 매 작업(파일 생성/수정/빌드/Git 풀 및 동기화 전후) 직후 반드시 자동 삭제(`find . -name "._*" -delete` 또는 `dot_clean .`)**합니다.
  - 저장소 동기화(`git pull`, `git push` 등) 시 외부 또는 로컬에서 유입되거나 생성된 모든 `._*` 파일 역시 발견 즉시 무조건 100% 삭제합니다.
  - 어떠한 경우에도 작업 디렉토리 내에 `._*` 파일이 잔류하지 않도록 철저히 관리하며, Git 스테이징 및 커밋 전 항상 전수 점검하여 100% 삭제 상태를 유지합니다.
